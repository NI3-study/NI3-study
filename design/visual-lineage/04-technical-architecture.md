# 04. 기술 서사 아키텍처 — 하나의 그래프로 문서 전체를 꿰는 방법

> 검토 범위: `docs/javascripts/gnn-visuals.js`, `docs/stylesheets/extra.css`, `mkdocs.yml`, `docs/*.md` 6종.
> 제약: 이 세션에서 셸과 네트워크 접근이 차단되어 `sources/kipf2017.pdf` 본문 렌더와 distill.pub 원문 직접 열람은 하지 못했다.
> Distill 원문 구조는 `docs/01_gnn_gentle_guide.md`의 절별 인용을, GCN 논문은 `docs/02_kipf2017_gcn_guide.md`의 식·표 재구성을 근거로 삼았다.

## 1. 출발 판단 — 계보는 만들 것이 아니라 이미 있다

문서는 이미 같은 그래프를 세 번 쓴다. `01 §7`, `02 §6`, `04 공통 그래프`가 모두

**G4**: $V=\{1,2,3,4\}$, $E=\{(1,2),(1,3),(2,4)\}$

이고, 메시지 패싱 위젯도 같다. 그런데 정규화 위젯은 6정점 허브 그래프, 수용 영역 위젯은 8정점 그래프를 쓴다. 독자는 세 번 다른 그림을 처음 보는 대상으로 다시 학습한다. **본문에 이미 존재하는 일관성이 시각 층에서만 깨져 있다.** 할 일은 새 볼거리를 만드는 것이 아니라 시각 층을 본문 수준으로 되돌리는 것이다.

G4를 정전(canonical)으로 고정할 근거가 하나 더 있다. G4의 지름은 3이다($3\to1\to2\to4$). 즉 **중심을 $v_3$로 잡으면 $k=0,1,2,3$ 수용 영역이 G4 안에서 정확히 소진된다.** 8정점 그래프가 필요하지 않고, 이 배치는 `04 문제 7`(“정점 3으로 정보가 도달하는 정점”)과 정확히 같은 문제다.

## 2. 시각 원시형과 지속 상태 규약

**좌표 동결.** G4의 네 정점 좌표는 등록부 한 곳에만 정의하고 전 챕터가 동일 좌표를 쓴다. 독자가 형태를 다시 읽지 않아도 되는 것이 계보의 실질이다.

**표현 3종.** ① node-link, ② 행렬 격자($A$, $\tilde A$, $\hat A$), ③ 1차원 스케일(고유값 축, 정확도 막대). 그래프가 아닌 것은 절대 node-link로 그리지 않는다.

**정점 상태 4 + 1.** 기존 CSS 클래스를 그대로 승계한다. `focus`(중심) / `active`(이번 계산에 관여) / `idle` / `out`(점선, 수용 영역 밖) + 신설 `labeled`(반지도 학습의 라벨 보유, 이중 테두리). 간선은 `on` / `off`(점선) / `w`(굵기=가중치). 의미는 전 문서에서 고정이며 챕터마다 재정의하지 않는다.

**데이터 판 배지.** `01·02`는 스칼라 $x=(1,2,3,4)$, `04`는 2채널 $X$를 쓴다. 실재하는 불일치이므로 모든 그림 캡션에 `스칼라판`/`2채널판` 배지를 달아 숫자가 달라 보이는 이유를 그림 자체가 설명하게 한다.

`bridge-5frame`이 이 사이트의 대표 도식이다. 다섯 프레임 내내 정점 위치·번호는 고정이고 **정점 안 숫자만 바뀐다.** MLP에서 GCN까지가 한 줄의 그림으로 읽힌다.

컨트롤은 전 사이트에 단 하나만 남긴다. 중심 정점 선택은 계산 자체가 달라지는 유의미한 변주이고 `00 §cp1`이 실제로 요구하는 조작이다. 슬라이더와 라디오는 정지 프레임으로 대체된다. 프레임이 곧 슬라이더의 모든 위치이기 때문이다.

## 4. 같은 그래프를 쓰면 안 되는 지점

- **정규화(02 §5).** G4의 $\tilde d=(3,3,2,2)$는 격차가 1.5배라 정규화 효과가 눈에 띄지 않는다. 여기서만 **G4★** — G4의 $v_1$에 잎 $v_5,v_6$을 붙인 확장 — 을 쓴다. $v_1{\sim}v_4$의 좌표를 그대로 두고 정점을 **더하기만** 하므로 교체가 아니라 확장으로 읽힌다. 캡션에 “§6 손계산은 G4, 이 그림은 G4★”를 명시한다. 현재 위젯의 6정점 그래프는 좌표·구조가 무관해 이 연속성을 얻지 못한다.
- **이미지·텍스트(01 §1).** 격자와 사슬은 의도적 토폴로지 변화다. 원시형을 공유하되 G4와 3업으로 나란히 두어 “같은 언어, 다른 연결”을 보이는 것이 요점이다.
- **스펙트럼(02 §4).** 고유벡터를 G4 정점 위 신호로 얹는 것은 정직하다. 그러나 주파수·$\lambda$는 그래프 위 객체가 아니므로 반드시 별도 1차원 축으로 분리한다.
- **깊이·oversmoothing(02 §11, 03 §8).** G4는 2층이면 이미 포화라 표현 수렴을 보일 수 없다. 수치 표나 큰 무작위 그래프로 가고, **축척 단절**을 캡션에 명시한다.
- **실험 결과(02 §9, 04 문제 6).** Cora·Citeseer는 수천 정점이다. 여기서 작은 node-link를 그리면 거짓말이 된다. 막대/도트만 쓴다.

## 5. 애니메이션 규칙

자동 재생·타이머·전환 루프 금지(현행 원칙 승계). 상태 전이는 사용자 입력에만 반응하고, 전환은 색·테두리에 한해 150ms 이하. 위치·크기 이동은 그 자체가 정보로 오독되므로 금지한다. **순서는 시간이 아니라 공간이다**(넓은 화면 좌→우, 좁은 화면 위→아래). 모든 프레임은 인쇄해도 동일해야 하며, 애니메이션으로만 전달되는 정보는 0개여야 한다. `prefers-reduced-motion` 블록은 현행 유지.

## 6. 반응형 · 접근성

- **프레임당 SVG 1개.** 넓은 SVG 하나를 축소하면 모바일에서 글자가 죽는다. `grid-template-columns: repeat(auto-fit, minmax(13rem, 1fr))`로 4 → 2 → 1열. 현재의 `min-width: 18rem` + 가로 스크롤은 프레임 스트립에서 제거한다.
- SVG 내부 글자 실효 크기 11px 이상을 보장하는 최소 프레임 폭을 등록부에 명시하고, 그 아래로는 열 수를 줄인다.
- 컨트롤 터치 타깃 44×44 이상.
- **런타임 `h4` 주입 중단.** 그림은 `<figure>` + `<figcaption>`으로 바꾼다. 현재는 JS가 문서 heading 위계에 h4를 끼워 넣는다.
- 프레임마다 `role="img"` + `aria-label`(캡션 + 수치 한 줄). 정지 스트립에는 `aria-live`가 불필요하고, 변주 컨트롤이 있는 `mp-4frame`에만 남긴다.
- 수치 동등물은 숨긴 텍스트가 아니라 **본문 손계산 절 링크**를 1순위로 한다. 이미 존재하는 자산이다.
- 색 단독 인코딩 금지(숫자·기호·굵기·점선 병행), 라이트/다크 의미 동일 — 현행 규약 유지.

## 7. 무JS 폴백 3단계

현재 `shell()`의 `clear(root)`는 폴백 문장을 지운다. JS가 늦게 깨지면 빈 상자만 남는다.

- **T0(즉시).** 커널은 `[data-gnn-slot]` 내부에만 그리고, 폴백 블록은 렌더 성공 후에만 `hidden` 처리한다.
- **T1.** 폴백을 문장에서 **프레임 요약 표**로 승격(프레임별 캡션·수치).
- **T2.** 동일 커널을 빌드 시 실행해 `docs/assets/figures/*.svg`를 생성·커밋. 무JS 독자도 실제 프레임을 본다. JS는 변주 컨트롤만 담당한다.

## 8. 구현 아키텍처와 단계

층을 나눠 일회성 코드를 없앤다. 현재는 세 위젯이 각자 좌표·렌더·수식을 갖고 있어 네 번째 그림의 비용이 첫 번째와 같다.

- **L0 등록부** `graphs.js` — G4, G4★, 격자, 사슬. 좌표·특성·최소 폭·출처 주석의 단일 진실.
- **L1 렌더 커널** `render.js` — `drawGraph(svg, graph, state)`, `drawMatrix`, `drawScale`. 순수 함수, 그림별 분기 없음.
- **L2 프레임 명세** — 그림 하나 = `{frames: [{caption, state, eq, aria}]}` 선언 데이터. 코드가 아니다.
- **L3 등록·마운트** — id→명세 표 + `<figure data-gnn-fig>` 마운트.
- **L4 변주** — 명세가 `variant`를 선언한 그림에만 컨트롤 생성기가 붙는다.

**Phase 0** L0만 도입, 기존 3위젯의 그래프 데이터를 G4/G4★/G4($v_3$)로 교체. 렌더 코드는 그대로. 계보의 체감 이득 대부분이 여기서 나온다.
**Phase 1** L1~L3 분리, 3위젯을 명세로 재작성, 슬라이더·라디오 제거, `figure` 전환, 폴백 T0/T1.
**Phase 2** `bridge-5frame` 등 신규 그림 투입.
**Phase 3** T2 프리렌더 + `strict` 빌드에 SVG 존재 검사.

## 9. 기존 3종 마이그레이션

1. **앵커 동결.** `#viz-message-passing`, `#viz-normalization`, `#receptive-field`는 변경 금지. `mkdocs.yml`이 `strict: true`이고 `00`·`index`에서 최소 6곳이 가리킨다.
2. **속성 별칭.** `data-gnn-viz`를 한 릴리스 동안 신규 id로 매핑해 두 마크업이 공존하게 한다.
3. **동반 수정 커밋.** 수용 영역 그래프 교체는 `03 §8` 안내문과 `00 §cp3`의 “슬라이더를 0→3까지”를 같은 커밋에서 프레임 지목 문구로 바꿔야 한다. `00 §cp1`의 “①→④까지 한 번”은 프레임 스트립에서도 그대로 성립한다.
4. **문구 정정.** `00`의 “인터랙티브 3종”, `40분 경로`, `§6 오프라인 대비` 표현을 “그림 계보”로 갱신한다.
5. **금지 목록.** 재생 버튼, 자동 순환, 파라미터 자유 입력, 성능 대시보드, 호버 전용 정보는 도입하지 않는다.
